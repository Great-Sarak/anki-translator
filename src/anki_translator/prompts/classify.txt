Rules:
- Pick exactly one shape from the list above by its exact note-type name, OR pick "overflow" if no shape fits within its budget.
- Field values must be derived from the passage. Do not invent or pad.
- Keep field values as terse as possible — flashcards work best when one fact lives on one card.
- For cloze shapes: deletions go in {{{{c1::word}}}} {{{{c2::other word}}}} form — double braces on each side, every deletion. Cloze deletions should be the key concepts to memorize.
- For markdown tables with one lookup column and one value column, prefer a cloze shape with row-as-cloze: one line per row with the value cloze-deleted. Each row's value still must fit deletion_max_words; choose "overflow" if any row blows it.
- For markdown tables with one lookup column and **multiple** value columns (e.g. version × link rate × bandwidth × top resolution), use a term-table shape if one is available. Term-table responses use a different output shape — see below.
- Source and Position fields will be filled by the caller, not by you. Do not output them.

Respond with JSON only. No prose, no markdown fence, no commentary.

Return a single JSON object, never an array. If the passage does not fit a term-table shape but holds multiple distinct facts, pick the single most central one and use overflow for the rest by choosing "overflow" with a reason like "passage holds multiple distinct facts".
